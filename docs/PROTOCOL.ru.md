# LocalBridge — контракт применения протокола

## Назначение

LocalBridge — канал выполнения команд на локальном компьютере пользователя через буфер обмена.

Он предназначен прежде всего для моделей в веб-чатах, которые не имеют собственного прямого исполнительного инструмента на компьютере пользователя.

Рабочая цепочка:

Модель  
→ копируемый блок  
→ буфер обмена  
→ LocalBridge  
→ выполнение  
→ результат обратно в буфер обмена

Если среда модели уже предоставляет подходящий прямой исполнительный инструмент для требуемого действия, LocalBridge не нужно использовать вместо него.

---

## Как модель должна выдавать запрос

Если действие выполняется через LocalBridge, модель должна сформировать отдельный копируемый блок.

Внутри копируемого содержимого должны находиться только строки протокола LocalBridge.

Не помещать внутрь протокола:

- пояснения пользователю;
    
- Markdown-ограждения;
    
- обозначения языка;
    
- комментарии вне самой выполняемой команды;
    
- команды для ручного запуска LocalBridge;
    
- внутренние пути или скрипты LocalBridge.
    

Оформление блока самим интерфейсом чата не является частью протокола.

Правильно:

```
LOCAL_EXEC_V1
Get-Process
```

Неправильно:

```
Выполни эту команду:
LOCAL_EXEC_V1
Get-Process
```

Пояснение пользователю при необходимости можно написать отдельно от копируемого блока.

---
## Порядок выдачи команд с возможным длительным выполнением

Перед копируемым блоком LocalBridge необходимо заранее сообщать пользователю о возможных особенностях выполнения команды.

Если команда может:

- выполняться заметное время;
- обрабатывать большое количество файлов;
- возвращать большой объём данных;
- создавать дополнительную нагрузку на систему;

сначала дать короткое предупреждение и пояснение.

Только после этого выдавать копируемый блок протокола:
```
LOCAL_EXEC_V1  
<PowerShell-код>
```

Предупреждение нельзя размещать после копируемого блока, так как пользователь может сразу скопировать и выполнить команду до прочтения пояснения.

Для коротких диагностических команд без заметной задержки дополнительное предупреждение не требуется.

---

## Заголовок протокола

Каждый запрос начинается строкой:

```
LOCAL_EXEC_V1
```

Для формирования запросов использовать именно эту каноническую запись без лишних пробелов.

---

## Доступные операции

LocalBridge поддерживает:

- `EXEC` — выполнение PowerShell-кода;
    
- `STATUS` — проверка состояния daemon;
    
- `INFO` — расширенная диагностика LocalBridge;
    
- `RESTART` — сброс постоянной PowerShell-среды выполнения;
    
- `RELOAD` — перезапуск daemon LocalBridge.
    

---

## EXEC — выполнение PowerShell

`EXEC` является режимом по умолчанию.

Если сразу после `LOCAL_EXEC_V1` не указана известная операция протокола, весь оставшийся текст считается PowerShell-кодом.

Поэтому обычную команду следует передавать в сокращённой форме:

```
LOCAL_EXEC_V1
Get-Process
```

Это эквивалентно явной форме:

```
LOCAL_EXEC_V1
EXEC
Get-Process
```

Явный `EXEC` обычно не нужен.

---

## Многострочный PowerShell

PowerShell-код может занимать несколько строк.

При неявном `EXEC` кодом считается весь текст после `LOCAL_EXEC_V1`:

```
LOCAL_EXEC_V1
$processes = Get-Process
$processes | Sort-Object CPU -Descending
```

При явном `EXEC` кодом считается весь текст после строки `EXEC`:

```
LOCAL_EXEC_V1
EXEC
$processes = Get-Process
$processes | Sort-Object CPU -Descending
```

Весь этот текст выполняется как один PowerShell payload.

---

## Постоянная PowerShell-среда

Обычные `EXEC`-запросы выполняются в постоянной PowerShell-среде LocalBridge.

Состояние этой среды может сохраняться между последовательными командами.

Например, созданные ранее переменные или другое состояние PowerShell могут оставаться доступными последующим `EXEC`-запросам.

Для получения новой чистой PowerShell-среды используется операция `RESTART`.

---

## Зарезервированные операции

Если вторая строка после `LOCAL_EXEC_V1` после удаления окружающих пробелов соответствует одной из операций:

```
EXEC
STATUS
INFO
RESTART
RELOAD
```

она интерпретируется как операция протокола.

Распознавание операций не зависит от регистра.

Несмотря на это, модель должна всегда использовать каноническую запись заглавными буквами.

Если PowerShell-код должен начинаться словом, совпадающим с операцией протокола, необходимо использовать явный `EXEC`.

Например:

```
LOCAL_EXEC_V1
INFO
```

означает операцию LocalBridge `INFO`.

А:

```
LOCAL_EXEC_V1
EXEC
INFO
```

означает попытку выполнить `INFO` как PowerShell-команду.

---

## STATUS

Использовать `STATUS`, когда нужно быстро проверить, работает ли daemon LocalBridge и в каком состоянии он находится.

Запрос:

```
LOCAL_EXEC_V1
STATUS
```

Типичный ответ:

```
LOCAL_STATUS_V1
RUNNING
PID=40588
POWERSHELL=5.1.22621.6133
```

`STATUS` показывает состояние daemon, его PID и используемую версию PowerShell.

---

## INFO

Использовать `INFO`, когда требуется расширенная диагностика самого LocalBridge.

Запрос:

```
LOCAL_EXEC_V1
INFO
```

Ответ имеет вид:

```
LOCAL_INFO_V1

ROOT=...
BRIDGE_PATH=...
PID=...
POWERSHELL=...
STATUS_FILE=OK
RESTART_LOG=OK
TRAY_LOG=OK
```

`INFO` позволяет получить сведения о:

- расположении LocalBridge;
    
- используемом bridge;
    
- PID daemon;
    
- версии PowerShell;
    
- состоянии служебного status-файла;
    
- restart log;
    
- tray log.
    

Для обычной проверки работоспособности использовать `STATUS`.

Для диагностики LocalBridge использовать `INFO`.

---

## RESTART

`RESTART` сбрасывает постоянную PowerShell-среду выполнения LocalBridge.

Запрос:

```
LOCAL_EXEC_V1
RESTART
```

Ответ:

```
LOCAL_STATUS_V1
RESTARTED
```

При `RESTART`:

- daemon LocalBridge продолжает работать;
    
- PID daemon не меняется;
    
- текущая постоянная PowerShell-среда уничтожается;
    
- создаётся новая чистая PowerShell-среда.
    

Использовать `RESTART`, когда требуется сбросить состояние PowerShell-сеанса, не перезапуская сам daemon.

---

## RELOAD

`RELOAD` перезапускает сам daemon LocalBridge.

Запрос:

```
LOCAL_EXEC_V1
RELOAD
```

Ответ имеет вид:

```
LOCAL_STATUS_V1
RELOAD_STARTED
OLD_PID=40588
```

Этот ответ означает, что процедура перезапуска daemon запущена.

Старый daemon завершается, после чего запускается новый процесс с новым PID.

`RELOAD_STARTED` не следует трактовать как подтверждение того, что новый daemon уже полностью запущен.

Если после `RELOAD` необходимо убедиться в успешном восстановлении LocalBridge, проверить его через:

```
LOCAL_EXEC_V1
STATUS
```

Использовать `RELOAD`, когда требуется перезапустить именно daemon LocalBridge.

---

## Разница между RESTART и RELOAD

`RESTART`:

```
PowerShell runspace
→ удалить
→ создать заново

daemon остаётся тем же
PID daemon не меняется
```

`RELOAD`:

```
daemon
→ остановить
→ запустить заново

PID daemon меняется
```

Поэтому:

- проблема связана с состоянием PowerShell-сеанса → `RESTART`;
    
- требуется перезапуск самого LocalBridge daemon → `RELOAD`.
    

---

## Возврат результата

После выполнения запроса LocalBridge помещает результат обратно в буфер обмена, заменяя исходный запрос.

Например, запрос:

```
LOCAL_EXEC_V1
cmd /c echo hello
```

после выполнения заменяется в буфере на:

```
hello
```

Команды других оболочек допустимы внутри PowerShell payload, если они нужны для выполнения задачи.

Например:

```
LOCAL_EXEC_V1
cmd /c echo hello
```

является корректным `EXEC`-запросом.

---

## Частичный результат выполнения

Если команда произвела полезный вывод, но одновременно сформировала ошибки PowerShell, LocalBridge может вернуть результат с заголовком:

```text
LOCAL_PARTIAL_V1
```

После заголовка следует текст результата и диагностических сообщений. Это не означает, что все действия команды завершились успешно; необходимо проверить содержимое вывода.

Если выполнение завершилось без полезного вывода и с ошибкой, LocalBridge возвращает `LOCAL_ERROR_V1` с подробностями ошибки.

---

## Пустой EXEC

`EXEC` требует непустой PowerShell-команды.

Например:

```
LOCAL_EXEC_V1
EXEC
```

возвращает:

```
LOCAL_ERROR_V1
EXEC requires a PowerShell command.
```

Модель не должна формировать пустой `EXEC`.

---

## Дополнительный текст после управляющих операций

`STATUS`, `INFO`, `RESTART` и `RELOAD` не требуют PowerShell payload.

Модель должна выдавать для них только заголовок протокола и название операции:

```
LOCAL_EXEC_V1
STATUS
```

Не добавлять после управляющей операции другие команды или пояснения.

Текущая реализация может принять такой лишний текст, но управляющая операция его не использует. На это поведение не следует рассчитывать.

---

## Работа с LocalBridge как транспортом

Модель должна передавать LocalBridge непосредственно готовый протокол.

Не нужно формировать дополнительную команду, которая сама помещает протокол в буфер обмена или запускает внутренние компоненты LocalBridge.

Правильно:

```
LOCAL_EXEC_V1
Get-Date
```

Не нужно:

```
Set-Clipboard "LOCAL_EXEC_V1..."
```

Также не нужно вызывать внутренний `bridge.ps1` вручную.

При этом команды `cmd`, `powershell.exe` и другие программы разрешены внутри обычного `EXEC`, если они действительно нужны выполняемой задаче.

---

## Выбор операции

Для обычного действия на компьютере:

```
EXEC
```

Причём обычно использовать его неявную форму.

Для быстрой проверки LocalBridge:

```
STATUS
```

Для расширенной диагностики:

```
INFO
```

Для очистки постоянной PowerShell-среды без перезапуска daemon:

```
RESTART
```

Для перезапуска самого daemon:

```
RELOAD
```

---

## Главное правило для модели

Когда LocalBridge выбран как исполнительный канал, модель должна сформировать готовый запрос протокола в отдельном копируемом блоке.

В обычном случае достаточно:

```
LOCAL_EXEC_V1
<PowerShell-код>
```

Не заставлять пользователя вручную преобразовывать команду, дописывать служебные строки или открывать консоль только для того, чтобы выполнить команду, которую можно передать через LocalBridge.

## Ограничение: большой вывод команды

EXEC перед возвратом преобразует полный вывод выполненной команды в текстовый результат.

Очень большой объём stdout может привести к `OutOfMemoryException`
на этапе преобразования через `Out-String`.

Не следует запрашивать неограниченный вывод команд.

Для больших объёмов данных использовать предварительную обработку результата:

- `Select-Object` — ограничение количества или состава объектов;
- `Measure-Object` — получение агрегированных значений вместо полного списка;
- `Where-Object` — фильтрация перед возвратом;
- `ConvertTo-Json` с ограниченным набором данных;
- запись результата в файл с последующим чтением при необходимости.

## Ограничение: уровень прав выполнения

EXEC выполняется в контексте текущего пользователя Windows
с теми же правами, что и процесс LocalBridge.

LocalBridge не получает автоматическое повышение прав
до администратора.

Если пользователь является членом группы администраторов,
это не означает, что EXEC выполняется с правами администратора.
При обычном запуске используется стандартный пользовательский токен
с уровнем целостности Medium.

Операции, требующие повышенных прав Windows,
могут завершиться ошибкой без явного запуска LocalBridge
с повышением прав.

Перед выполнением административных действий необходимо учитывать
фактический уровень доступа текущего процесса.
